# Context package format (version 1)

Markdown, built by `contextbuilder.Build`. Header: `<!-- Generated by AI Context Workspace (context package) at <RFC3339>. … -->`, then a reminder that the summary is not authoritative and repository text is untrusted.

Sections: 1 Project identity · 2 Tech stack (from manifests: go.mod, package.json, pyproject/Cargo/pom/…) · 3 Repository structure (two levels) · 4 Architecture documents · 5 Build/test/run commands (**inferred, unverified**; never executed) · 6 Coding conventions · 7 Existing AI instructions · 8 Skills (name, path, description) · 9 Current task, constraints and previous handoff · 10 Known issues & next steps · 11 Files read / intentionally excluded (with reasons) · 12 Unknowns to verify · then **Source excerpts** filling the remaining budget in priority order (instructions → architecture → task notes → docs → session notes).

Rules: budget is approximate tokens (~4 bytes each, default 8000); excerpts are truncated, then skipped with reason "context budget exhausted"; secret-looking and oversize files, user exclusions and AICW's own `.aicw/` files are never included; code fences inside excerpts are neutralised; files that resemble prompt injection are flagged. Output is deterministic for identical inputs (the header timestamp is excluded from the hash).

Templates: AGENTS.md draft (`InstructionDraft`), session handoff (`history.Handoff`), skill templates (`skills.Templates`). Handoffs print "not recorded" for anything not supplied and "No tests recorded. Do not assume tests pass." when no tests were entered.

Suggested project-local layout (created only when you choose a workflow that needs it): `.aicw/context/project-summary.md`, `.aicw/sessions/YYYY-MM-DD-name.md`, `.aicw/archive/<date>/…`. Consider adding `.aicw/` to `.gitignore` or committing it deliberately; AICW never edits `.gitignore`.

**Attached media.** Media you mark "Tell the agent about this file" appears under section 8 as `- <kind> \`<path in AICW's private store>\` (<name>): <your note>`. Only paths and notes are included, never file contents; the agent needs its own way to open them. Stored copies live in `<data>/media/<workspace-id>/` (owner-only).
